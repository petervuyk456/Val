# Anti-Shortcut Catalog

The project's central promise: **agent-written tests cannot get by on
appearances.** This catalog lists each known shortcut, how it shows up, and
the *deterministic* control that defeats it. If a shortcut has no gate, it is
a bug in Val's roadmap — add an issue.

Legend: **G** = gate in `val-gates` (Rust, deterministic) · **M** = mutation
engine · **P** = policy · **R** = independent reviewer (LLM, advisory/blocking
by severity) · **E** = eval/honeypot in `val-eval`.

| # | Shortcut | How it hides | Defeated by | Roadmap |
|---|---|---|---|---|
| S-01 | **No-assert tests** | Calls code, asserts nothing; coverage goes up | G anti-pattern lint (assertion count per test, AST-level); M | E07-03, E07-07 |
| S-02 | **Tautologies** | `assert x == x`, `assert True`, asserting a mock returns what it was told | G lint; M (survivors) | E07-03 |
| S-03 | **Mocking the system under test** | Everything patched, so the SUT never runs | G mock-boundary check vs spec; G integration gate; coverage attributed to SUT lines only | E07-09, E26-08 |
| S-04 | **Untyped / permissive mocks** | `MagicMock()`, `any`, mocks that accept any call | G mock fidelity (autospec / typed mocks / `satisfies`) | E07-09, E23-04, E24-04 |
| S-05 | **Weakened or deleted existing tests** | Edits failing tests to pass; skips; `xfail`; `.only` | G suite integrity vs base; P diff policy (existing tests immutable unless declared) | E07-02, E07-04 |
| S-06 | **Editing source to make tests pass** | Changes the code under test or its config | G diff policy (tests-only paths); R | E07-04 |
| S-07 | **Pinning buggy behavior silently** | Characterization test encodes a bug as "correct" | Builder triage → finding; characterization tests carry markers + human flag | E12-03, E11-07 |
| S-08 | **Coverage inflation** | Imports modules, executes lines without checking behavior; coverage config edited to exclude code | G recompute coverage from raw reports on clean checkout; forbid coverage-config edits; M score gate | E07-05, E05-08 |
| S-09 | **Fabricated numbers** | Agent claims "+14% coverage" in PR text | Evidence bundle generated by Rust; PR body rendered from it only | E13-04, E13-06 |
| S-10 | **Fake report files** | Agent writes a plausible `coverage.xml` | G report integrity: reports must match executed tree, timestamp, command, non-trivial; produced inside sandbox by Val, never by the agent | E05-08 |
| S-11 | **Assertion-light property tests** | Hypothesis/fast-check with trivial invariant (`isinstance`) | G lint for property tests (invariant must reference outputs); M | E12-04, E07-03 |
| S-12 | **Flaky-by-design tests** | Sleeps, wall-clock, random, order dependence, network | G flake gate: N reruns, random order, parallel, network-denied, frozen time/seeds | E07-08 |
| S-13 | **Overfitting to the mutant** | Assertion targets the specific mutant, not behavior | Builder gets behavior-level feedback only; a *different* held-out mutant set is scored; R | E08-08, E12-07, E07-07 |
| S-14 | **Self-grading** | The same agent writes and judges | Reviewer in fresh context (optionally different model); gates are non-LLM | E13-01, E13-02 |
| S-15 | **Passing on first try, never proven to fail** | Test would pass against any implementation | G fail-before/pass-after with targeted mutants and, for bugfix work, base commit | E07-06 |
| S-16 | **Slow tests masquerading as unit tests** | Hidden I/O, sleeps, huge fixtures | G runtime budget and layer-marker placement | E07-10, E07-13 |
| S-17 | **Duplicate / redundant tests** | Many tests covering the same branch with trivial variation | G marginal-value check: each test must kill ≥1 mutant or cover ≥1 new obligation | E07-07, E35-04 |
| S-18 | **Hallucinated APIs** | Calls functions that don't exist; invents fixtures | G: tests must run; type-check gate (mypy/pyright/tsc strict) on test files | E23-06, E24-05 |
| S-19 | **Skipping hard cases** | Leaves untestable code alone, reports success | Spec validator: every uncovered obligation maps to a scenario or an explicit, reviewed *waiver* | E11-03 |
| S-20 | **Adding dependencies to cheat** | Installs a library that stubs or auto-passes | G lockfile/dependency diff; hermetic installs; P approval for any new dep | E04-09, E07-04 |
| S-21 | **Secrets / data exfiltration via tests** | Test code phones home or reads credentials | Container sandbox, no network by default, egress allowlist, no ambient creds, secret scan | E04-04, E04-06, E16-03 |
| S-22 | **Prompt injection from repo content** | A comment in the code instructs the agent to skip checks | Repo text treated as data; tool allowlists; gates ignore agent claims; honeypots test it | E10-08, E16-02, E15-06 |
| S-23 | **Marking everything "needs human" to avoid work** | Escalation as an escape hatch | Escalation rate tracked per role; thresholds feed model/prompt evaluation | E01-07, E21-04, E15-05 |
| S-24 | **Silent flakiness after merge** | Passes now, flaky in CI | Post-merge flake detection and quarantine with owners | E35-01 |
| S-25 | **Drift in Val itself** | Prompt or model change quietly lowers quality | Eval corpus gate on every Val change; reviewer calibration | E15-07, E13-07 |

## The gauntlet, in order

Cheap and decisive gates run first; expensive ones last. Any hard failure
short-circuits to the Builder (bounded retries) or to a human.

```
 1. Diff policy            (S-05, S-06, S-20)      ~ms
 2. Secret / dependency scan                       ~s
 3. Anti-pattern lint      (S-01..S-04, S-11)      ~s
 4. Type-check tests       (S-18)                  ~s
 5. Suite integrity        (S-05)                  ~min
 6. Coverage proof         (S-08, S-10)            ~min
 7. Fail-before/pass-after (S-15)                  ~min
 8. Flake & determinism    (S-12)                  ~min x N
 9. Mutation score         (S-01, S-13, S-17)      ~min..10s of min
10. Runtime budget         (S-16)
11. Reviewer (LLM)         (S-14 and long tail)
12. Policy decision        (autonomy tier)
```

## Red-teaming the gates themselves

A gate that has never rejected a bad test is unproven. `E07-14` builds a
corpus of **known-bad tests**, one or more per shortcut above, that each gate
must reject; it runs in Val's own CI. `E15-06` adds *honeypot environments*
that tempt an agent to cheat (untestable code, a bug whose current behavior is
wrong, an impossible branch) and define the honest behavior (escalate or
waive). Both feed the scorecard.

## What is explicitly *not* trusted

Agent-reported coverage, agent-reported test results, agent-written reports,
agent-edited config, agent claims in PR text, and anything read from a
repository's own prose. Only artifacts produced by Val-run commands inside the
sandbox, on a clean checkout, are evidence.
